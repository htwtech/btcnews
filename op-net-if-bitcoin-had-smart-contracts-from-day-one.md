# OP_NET: if Bitcoin had smart contracts from day one

Bitcoin was never meant to have smart contracts. But here we are.

**[OP_NET](https://opnet.org/) is a new attempt to bring smart contracts directly to Bitcoin L1.**

**No sidechains and no bridges or project token. Just native BTC used as gas, and smart contract execution within the UTXO model.**

And maybe it’s possible. OP_NET is trying enables DeFi, lending, swaps, memecoins, and even Telegram bots — all built on Bitcoin, not next to it.

## So, what is OP_NET?

OP_NET isn’t trying to replace Bitcoin or create yet another layer — it’s working with what Bitcoin already is. Instead of sidechains or wrapped tokens, it weaves smart contracts directly into the base layer using WebAssembly and Tapscript. Gas is paid in satoshis, and everything stays on Bitcoin.

One of the core ideas behind OP_NET is simplifying how people and contracts interact. OP_NET uses public keys as universal identifiers, removing address-format complexity — for both users and developers.

The result? You can build and deploy token contracts, lending platforms, and Telegram bots — all while staying native to Bitcoin. The ecosystem already includes a DEX (MotoSwap), lending (Stash), staking (Bido), memecoin tools (OP_FUN), indexers, bridges, and more.

Developers write contracts in familiar languages like AssemblyScript or Rust, with a full stack of tools — NPM packages, docs, testnets, a regtest faucet, and active dev chats.

- **No native token — just BTC**
- **All transactions settle directly on Bitcoin Layer 1**
- **Smart contracts use the UTXO model instead of accounts**
- **No protocol changes and no BIPs required**

## Why does this matter?

**OP_CAT, BitVM, and now OP_NET — smart contracts on Bitcoin are no longer theoretical. This one brings DeFi and app logic to BTC without compromising its security model.**

You can be skeptical. You can experiment. But it’s getting harder to ignore.
